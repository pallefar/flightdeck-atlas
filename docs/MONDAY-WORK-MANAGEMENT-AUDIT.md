The reference is monday.com's published project-management workflow and product documentation, including actual workflow screenshots. This is a selected workflow comparison, not a claim of full product parity or a blind visual win against an authenticated monday workspace. Source ownership, Atlas permissions and its TE design are preserved.

## Atlas-specific additions

- Think like a CEO, VP or Director: explicit evidence, missing-input disclosure, decision posture and role-specific questions. Current, weekly and stage-gate contexts. Never claims to know an individual's thoughts or to have consulted an AI provider.
- Convert a reviewed recommendation into a normal editable task. The same role/recommendation cannot be added twice while its task exists. Save dated source-revision snapshots and export decision briefs. History is bounded by both count and available project space; oldest reviews roll off with a disclosed retention rule.
- Eat the Frog: deliberate selection of one accessible, active, unblocked task per user per local day; a first step, start time and 5–90-minute focus block. Saved in private account preferences. Starting focus uses the existing real timer without replacing an active/paused timer. Completion updates the actual task through normal project authorization.
- Project Eye replaces the old map name in all UI labels and tests. Provider/reference attribution retains the original upstream project name.

## Quality bar and critique

Acceptance uses actual persisted workflows: save/reload compound views; bulk changes leave unselected tasks unchanged; a dependent task's readiness updates once; explicit date ranges and milestones render; bad dates and stale revisions fail safely; time corrections retain identity; differing leadership roles cite actual inputs and create reviewable actions; private daily plans survive reload and reserve time without double counting; mobile content stays within the dialog.

Independent criticism caught time-correction loss, stale task/budget drafts, invalid-date timeline failures and oversized leadership history. These were corrected before publication. The first release passed 38 scenarios. The extended pass adds tests for formula bounds, scheduling, timer idempotency, shared-block conflicts, intake approval/rules, reminder cancellation, atomic transfer, template propagation and concurrent graph writes. All 47 automated scenarios passed in the final regression run, including a capacity-draft conflict check. The expanded dependency graph was verified within the 353px mobile dialog, and direct project links survive sign-in and reload. Final results are also recorded in build progress. Visual review led to improved action contrast in both themes and a wider mobile timeline date area. Results are recorded in build progress. No inaccessible authenticated monday experience was invented as evidence.

## Extended review findings

Independent review identified exponential repeated-formula evaluation, unsafe simultaneous dependency graph edits, inaccessible timer recovery, durable-record pagination, cancellation races, transfer recurrence duplication, currency changes, and creation paths missing rule/assignment processing. The extended implementation addresses these with bounded memoization, transactional revision/predicate guards, owner-only global timer recovery, separate record queries/cursors, permanent cancellation, exact record preservation on transfer, and a common work-mutation pipeline. Visual review drove compact project framing, a persistent mobile tool selector, corrected metric layout and normalized checkbox sizing.

## FlightDeck handoff

The new migration adds `atlas_work_records` for timers, reminders, forms, submissions, note blocks, recent presence and versioned playbooks. Project JSON now includes custom field definitions/values, typed schedule links, parent IDs, rates, widgets, rules, baselines and expense records. Include these in the eventual shared Supabase data migration. Project/member authorization remains enforced on the server. The OS SDK should supply authenticated identity, project access/revision APIs and a durable action runner before external or timed actions are enabled. No account migration or new shared-login mechanism was activated in this pass.
